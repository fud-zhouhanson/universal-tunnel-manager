网络体检 · 应急恢复

什么时候用它：网页打不开、App 连不上、明明显示「已加速」却没效果、改过 DNS 之后整台上不了网 —— 这些情况光看配置文件是查不出来的，因为路由表和 DNS 都只是「声明」，不是「事实」。
· 检查真实流量走向：真解析一次、真连一次、真看第一跳（TTL=1 的包会逼第一跳报出自己是谁）， 然后告诉你流量实际从哪出去、有没有被拽进隧道或黑洞、DNS 有没有被换成假 IP 池。
· 一键应急恢复：把默认路由、假 IP 池路由、DNS 和 DNS 缓存一次救回本机直连的干净状态（需要管理员密码，过程中网络会短暂中断）。
· 保存健康基线：在「现在一切正常」的时候存一份，以后应急恢复会优先还原它而不是清空。

自动追踪 · 新开的网站

开着之后，你浏览器里新打开的网站会自动出现在上面的路由表里；关掉超过 10 分钟没再看的会自动移除。
原理：每 30 秒只读扫一次浏览器历史（Chrome / Edge / Firefox / Safari）。不记录、不上传任何数据，只在本机内存里转一圈。
Safari 需要在「系统设置 → 隐私与安全性 → 完全磁盘访问」里给终端授权；没有权限时用下面的输入框手动加。

Steam 体检

Steam 不是一个网络，而是三张互不相干的网，它们可以分别走不同的出口 —— 这正是「明明在加速却没效果」的根源：
· 平台网（登录 / 好友 / 商店）：WebSocket 443，走 CM 集群 → 对应下文的「联机延迟」
· 游戏联机网：UDP 27015–27060，走 Valve 的 SDR 中继（杀戮尖塔这类游戏不是双方直连）→ 对应「联机稳不稳」
· 内容分发网（商店 / 下载）：HTTP，走你下载区域（CellID）对应的 CDN → 对应「下载走没走加速、多快」

① P2P 联机稳定性（采样实测）
联机质量单看配置得不出结论，必须在对局里边跑边采。
怎么用：进游戏开一局（最好已经和朋友联上）→ 回这里点「开始采样」→ 采样期间留在游戏里。 采样用 nettop 逐进程读 Steam 的收发字节数，不抓包、不上传、只在本机内存里转一圈。
② 联机延迟（平台网 + 游戏中继）
两个层面不能混为一谈：「CM 接入区延迟」是你登录 Steam、看好友与商店的延迟； 「中继 RTT」才是游戏联机数据包实际要走的路径质量。下面两栏分开列。

③ 商店与下载：走的是直连还是加速器
想看下载速度怎么测：在 Steam 里开始下载 → 回到这里点「① 开始采样」→ 得到的速率就是真实下载速度，同时会告诉你这些字节走了哪个网卡（物理 / 隧道）。
这里刻意不做「自动测速」：Steam 的下载分片需要 depot key 才能拉， 拿不到确定大小的文件，硬凑一个 Mbps 出来是假的 —— 真速度只能边下边测。
